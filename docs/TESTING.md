## 1. 业务引擎与数据完整性

测试文件：`tests/engine.test.ts`。

### 主链路

- 六个种子事件分别得到冲突、否认、已证实、待核实、更正后已证实、过期状态。
- 所有当前结论引用指向同事件的真实原文对象。
- 提取出主体、事项、类型与作用；高匹配候选仍由用户确认。
- 同源更正替代旧版本，保留旧原文，金额由 3,000 万更正为 2,800 万。
- 演示收购文本正确提取为更正，不把历史“未签署”误当作当前否认。

### 不确定性与独立来源

- 已核验公司来源中的观点、推测和传闻仍不能证实事件。
- 未核验事实、低权重社交信息不能确认或否认。
- 支持与否认同时存在时冲突；输入数组逆序不影响结果。
- 新传闻不能覆盖已核验公告的否认。
- 同源但没有明确版本关系的矛盾陈述仍保留冲突。
- 同一原始来源的转载不重复计算独立来源、不叠加权重。

### 时间与版本

- 按披露时间而不是抓取时间决定顺序。
- 回放时点不可见尚未披露或抓取的信息。
- 更正的披露时间必须晚于前版本。
- 新更正过期不能复活旧版本；连续多次更正同样适用。
- 有效期截止即退出当前依据。
- 未披露发生时间保留 null 并提示。
- 非法 ISO 时间、未来时间、抓取早于披露、更新早于抓取、有效期不晚于披露都拒绝保存。
- 跨事件、跨来源、自引用、不存在的前版本、无合法作用等版本关系拒绝。
- 已核验强事实不能被未核验/观点/低权重或建议性“更正”删除依据。

### 财务口径与归并边界

- 普通排版差异去重，但不混同 `1.5` / `15`、`+10%` / `-10%`。
- 同主体不同类型不归并；同类型不同事项和不同收购对象不套用旧主题。
- 第二季度与第三季度等不同报告期不因文字接近而高分归并。
- 不把“公告否认传闻”降级为传闻本身。

### 安全与备份

- 引用必须存在于原文，拒绝幻觉引用。
- `javascript:`、`data:` 等危险来源链接拒绝。
- 引用中的直接买卖建议/收益保证不升级为已证实结论。
- 备份 schema、ID 唯一性、事件引用完整性和证据校验；损坏记录不覆盖原始浏览器值。
- 无效备份、存储不可用、缺少链接与重复原文都不能被悄悄当作成功。

## 2. 模型代理

测试文件：`tests/server.test.ts`。通过 `createApp` 注入配置和模拟 fetch，再访问真实本地 HTTP 服务。

- 未配置模型返回 503 与明确 fallback，不伪装 AI 成功。
- 健康接口不泄露密钥，配置模式与连接可用性不混同。
- 有效 JSON 输入与七字段输出、源引用和消息隔离。
- 非法请求、长度限制、过大 body、非 JSON、未知 API。
- 请求原文中的指令只作为用户数据，不获得工具能力。
- 模型输出错误 JSON、字段类型/枚举错误、额外字段、空响应、幻觉引用被拒绝。
- 上游 4xx/5xx、网络异常、超时、过大返回、响应流异常不暴露远端原始 body 或密钥。
- 同源限制、限流与重试响应。
- 固定服务端地址，不抓取用户 URL，不跟随重定向。

这些测试证明代理与校验的行为，**不证明真实大模型的语义准确率、真实供应商可用性或金融数据真实性**。

## 3. 浏览器端到端

测试文件：`tests/e2e/product.spec.ts`。

每个场景在桌面和手机模拟视口执行：

1. 工作台六个事件、状态筛选、统计、截图。
2. 关键词、事件类型、空结果与清除筛选。
3. 时间线、结论引用、原始证据、四时间与冲突对照。
4. 导入示例 → 提取 → 选择前版本 → 归并 → 结论变化 → 刷新持久化 → 重复导入阻止。
5. 未选择前版本时保留冲突，不盲目覆盖。
6. 未核验新来源创建待核实事件，发生时间和原文链接缺失提示。
7. 空原文与未来披露拒绝导入。
8. 模型 API 失败明确显示规则回退。
9. 关注切换与刷新保存。
10. 资料库属性过滤并打开原文。
11. Markdown 简报、JSON 备份下载，损坏备份不能覆盖。
12. 无页面级横向溢出，弹窗可用 Escape 关闭。
13. 明确填写的不同原始来源链不被强行继承为同源，更正被阻止。
14. 否定性的更正不能反向确认为已签约。
15. 幻觉引用拒绝后，提取字段真正回退至本地规则。
16. 两个同源标签页不会静默覆盖，陈旧草稿暂停保存并可备份、刷新。
17. 已有 500 个事件时拒绝创建第 501 个，不写入不可恢复记录。

执行后 `playwright-report/index.html` 提供自动化报告；`test-results/` 提供工作台截图和失败时的追踪。这些是本地自动生成产物，不提交到源码仓库。`docs/screenshots/` 为保留交付的实际生产页面截图。

## 4. 初轮失败与修正记录

初轮业务测试发现四个断言失败，涉及三类真实缺陷：数字去重（两例）、报告期错配、公告否认的属性判断。保持测试预期，修改实现后全部通过。

独立审查随后发现否定更正、来源链继承、容量、跨标签页覆盖和模型回退残留问题。新增 `tests/integrity.test.ts` 六项回归及五类浏览器场景。跨页回归进一步发现初始读取的无意义重写会触发伪冲突，修复后两视口通过。最终格式化源码后重新完整执行：159 项单元/接口测试与 34 项浏览器测试全部通过。

详细开发修正经过见 `AI_USAGE.md`。

## 5. 尚未验证与已知限制

- 没有真实外部模型凭证，因此未做供应商端到端联调或提取质量评测。
- 没有接入扶摇/iFinD 真实数据，也没有模拟“真实金融数据调用成功”。
- 公网静态站与公开仓库已发布（见 `DEPLOYMENT.md`）；线上验收应使用无痕窗口打开 GitHub Pages URL。此前未完成远程发布的状态已更新。
- 手机覆盖是 Chromium 模拟，尚未覆盖真实 Safari/Android 设备、屏幕阅读器或完整 WCAG 审核。
- 自然语言数值冲突识别、复杂报告期同义表达、多事件拆分、同义公司名和关联标的推理不是通用完备实现；需要人工确认。
- 没有后台任务、多端同步、多人编辑和生产规模压力测试；浏览器容量有限，务必备份。
- 来源核验来自使用者声明；产品没有替用户核验外部公告真实性。

## 手工验收建议

优先复现 `DEMO.md` 的否认→更正路线，再检查未核验信息不会证实、清空有效期与缺失字段表现、错误恢复保持原记录。上线后还需在无痕浏览器验证真实 HTTPS 地址与静态模式回退。
