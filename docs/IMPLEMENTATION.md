# 溯知 Trace｜实现方案

## 1. 产品选择

不是新闻聚合器，而是可以复核的事件工作台。核心问题是：同一事项有哪些版本、谁最早说了什么、哪些证据改变了判断、哪些仍未被证实。

主链路：导入原文 → 提取主体/类型/事项键/陈述属性 → 候选匹配 → 人工确认归并或创建 → 证据入库 → 结论重新计算 → 原文及四类时间可回溯。

## 2. 技术方案

- React + TypeScript + Vite；轻量响应式界面，无外部字体和图片依赖。
- 纯函数证据引擎：评分、相似度、去重、版本替换、状态计算，可独立测试。
- 本地浏览器持久化，支持 JSON 备份和恢复；不收集真实持仓与身份信息。
- 可选 Node/Express 服务端调用 OpenAI-compatible 模型。密钥仅在环境变量。模型不可用时显式回退到规则提取；最终结论始终由可解释规则生成。
- 默认数据全部为虚构教学案例，不伪造交易所链接、实时行情或已连接数据源。

## 3. 核心数据

事件：ID、标题、主体、虚构标的代码、事件类型、事项键、标签。

证据：独立 ID、事件 ID、来源名/类型/URL、原文、引用、陈述属性（事实/观点/推测/传闻）、作用（支持/否认/更正/更新）、发生时间（可缺失）、披露时间、抓取时间、更新时间、有效期、前版本 ID、源文件/转载链 ID。

来源等级由使用者声明，不视为外部核验。默认案例为明确标注的模拟来源。官方来源身份未核验时不得得出“已证实”。

## 4. 状态与规则

- 评分是启发式证据权重，不是概率或投资置信度。
- 传闻、观点、推测不能单独确认为事实。
- 独立且有效的强支持/否认同时存在：证据冲突，不能简单“新覆盖旧”。
- 明确关联的更正/否认/更新替代其指向的版本；旧版本保留且标记被替代。
- 同一原始来源的转载不增加独立来源数；精确重复原文阻止导入。
- 时间排序采用披露时间而非抓取顺序；未来披露、无效时间、抓取早于披露等拒绝保存。
- 过期证据退出当前判断；无有效依据返回“已过期/待核实”，不静默维持结论。
- 只有同主体、同事件类型、同事项键才高匹配；低分需要另建，归并必须人工确认。

## 5. 产品页面

情报工作台（搜索、状态/类型筛选、排序、关注）、事件详情（当前判断、证据时间线、冲突对照、引用与四时间）、证据库（原文和来源筛选）、我的关注、数据与设置（AI/数据源状态、备份恢复）。

## 6. 验收

主链路以及否认、更正、冲突、过期、转载、缺失、错误日期、危险 URL、模型失败、非法模型字段、提示注入输入、归并边界均需验证。浏览器检查导入到事件详情、关注持久化、过滤、导出和移动端。

## 7. 边界

不生成确定性涨跌预测、收益保证或买卖建议。暂不接真实金融数据源，不宣称完成生产级真实性核验。静态托管可运行完整规则演示；模型能力需要单独运行同源后端。公网 URL 与远程仓库发布需对应账号授权，不自动进行 Git 提交或推送。
